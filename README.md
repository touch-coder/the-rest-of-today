# 眠记 · The Rest of Today

记录夜间睡眠、午休和补觉，查看每日图表、缺失月历及睡眠总结。网页版本数据保存在当前浏览器，首次加载并完成离线缓存后可断网记录。

仓库：[touch-coder/the-rest-of-today](https://github.com/touch-coder/the-rest-of-today)。网页部署地址以 GitHub Pages 当前设置为准；仓库重命名前的旧 Pages 地址不再作为权威入口。

## 移动应用进度

用户已确认 iOS 16+、Android 10+、Capacitor、SQLite 本地存储和本机提醒方案。共享业务逻辑已移入 `shared/`，原生存储、文件分享和提醒适配代码位于 `app/src/`，配置入口为 `capacitor.config.ts`。这些文件目前是未完成的原生桥接；iOS/Android 平台工程尚未生成，未完成设备构建或验证。生成工程前需成功安装 `package.json` 中的 Capacitor 依赖，并安装相应平台工具链。

网页当前通过 Node.js 内置服务器和复制构建脚本运行，不需要安装运行依赖。移动端构建需要安装开发依赖：

```sh
npm install
npm run mobile:sync
```

之后用 `npm run mobile:ios` 或 `npm run mobile:android` 打开对应原生工程。平台签名、应用商店发布和生成安装包不属于首轮本地构建验证。

## 运行

需要 Node.js 20 或更新版本，无需安装运行依赖。

```sh
npm run dev
```

电脑打开 `http://localhost:5173`。手机可在同一 Wi-Fi 下打开 `http://电脑的局域网IP:5173`，但普通 HTTP 局域网地址不支持离线安装；正式使用请部署到 HTTPS。可通过 `PORT=8080 npm run dev` 指定端口。

## 使用流程

1. 在设置中确认开始记录日期，默认当天；默认全天睡眠目标为 8 小时。
2. 在首页或月历选择醒来日期，填写估计入睡和最终醒来的完整日期时间。
3. 每天最多一段夜间睡眠、一次午休和一次补觉。记齐后点击“确认今日／当天完整”。
4. 没有夜间睡眠时视为未记录，即使已有午休或补觉。确实全天没有睡眠，且当天无任何记录时，可单独确认 0 小时。
5. 在睡眠总结查看每周总结和每月总结；只有已确认完整和明确 0 小时的日期参与正式统计，有记录天数单独统计周期内至少有一条睡眠记录的日期。修改记录后需要重新确认。
6. 在设置导出 JSON 备份；CSV 用于查看明细，不能恢复。导入 JSON 会先预览新增、重复和冲突，再合并。

## 已确认的计算规则

- 时区固定为北京时间（Asia/Shanghai），所有睡眠按醒来日期归属。
- 时长 = 最终醒来时间 − 估计入睡时间，不扣除中途清醒时间；单段最多 24 小时，时间不能重叠，相邻允许。
- 每周为周日至周六，每月为自然月；当前周期截至今天。
- 完整率分母为开始日期至当前周期截止日期内的天数，包含今天。过去缺失日期在月历标记，今天显示记录进度。
- 日均时长、达标率、类型占比仅使用已确认日期。缺失和待确认不按 0 小时计算。明确 0 小时参与分母。
- 目标带生效日期，历史按当时目标计算；初始目标为 8 小时。修改已有生效日期会重算对应历史目标。
- 夜间作息使用已确认的夜间睡眠；入睡时间以中午为分界展开，使 23:50 与 00:10 连续。波动使用总体标准差，少于 2 个夜间样本显示未知。
- 只补录更早的睡眠不会静默改变开始日期，会询问是否提前；范围外的数据保留但不参与统计。
- 删除确认后支持撤销最近一次删除；后续其他数据修改或重新加载会清除撤销入口。
- JSON 合并保留本地同 ID 记录、本地同生效日期目标。同日期类型或时间重叠的冲突记录跳过并报告；只有当日记录完全匹配时才恢复备份的完整确认。
- 7 天备份提醒在打开应用时显示，应用关闭时不会推送通知。导出后请确认文件实际保存成功。

## GitHub Pages 部署（推荐）

项目已包含 `.github/workflows/pages.yml`，推送 `main` 时自动执行语法检查、核心测试、构建和发布。Pull Request 只检查，不发布。构建无第三方依赖，无需 `npm install` 或配置密钥。

1. 创建公开 GitHub 仓库并推送源码。
2. 在仓库 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
3. 推送 `main` 或在 Actions 中手动运行 **Test and deploy GitHub Pages**。
4. 等待部署成功，打开 Pages 设置给出的 HTTPS 地址；项目仓库通常为 `https://用户名.github.io/仓库名/`。

`.gitignore` 排除了构建产物、测试截图、睡眠 JSON/CSV 备份、环境文件和本地协作记录。提交前仍应检查文件列表。睡眠记录保存在浏览器中，不会随源码推送；迁移到线上地址前导出 JSON，再在新地址导入。

部署使用 GitHub Actions 的内置短期令牌；不需要保存个人访问令牌。每次网页资源更新要修改 `sw.js` 缓存版本，以便已有设备收到更新提示。

## 其他 HTTPS 部署

```sh
npm run build
```

将 `dist/` 中的内容上传到支持 HTTPS 的静态托管平台，例如 Cloudflare Pages、Netlify、Vercel 或已有静态服务器。构建命令为 `npm run build`，发布目录为 `dist`。无需数据库、后端、环境变量或密钥。部署到子目录也支持，务必保留文件目录关系。

线上地址首次打开后，到“设置与备份”确认“离线资源已就绪”，再添加到手机主屏幕。iPhone 使用 Safari 分享菜单；Android 使用浏览器的安装入口。

每次更新程序资源应修改 `sw.js` 的缓存版本号，重新构建部署。已有用户会看到更新提示，确认后重新加载；睡眠数据保留在浏览器存储中。

当前发布方案采用 GitHub Pages，线上地址以部署成功后的 Pages 输出为准。开发预览不是永久线上地址。

## 数据边界

- 无账号、无设备同步、不上传睡眠数据，不使用在线 AI。
- 每个设备、浏览器、网址拥有独立存储。清除网站数据、更换地址或浏览器都可能失去访问；用 JSON 备份迁移。
- 浏览器存储读取失败时不会自动覆盖原始数据；设置页提供原始数据导出及备份恢复入口。
- Chromium 浏览器集成流程曾在首版验证；本次源码迁移后需要重跑浏览器测试。iOS/Android 原生工程尚未生成；依赖下载和对应平台工具链可用后，再执行 `npm install`、`npm run mobile:sync` 并分别验证原生构建。
